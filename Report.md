## 1. Класи сутностей і тестові дані
- `Course(id, title, credits)`: курс.
- `Student(id, name, age, course_id)`: студент, пов'язаний із курсом через `course_id`.

Тестові дані (`data.py`): **10 курсів** і **20 студентів**. Для порівняння продуктивності додатково генеруються великі набори: 200 000 студентів / 200 курсів і 20 000 студентів / 200 курсів (фіксований `seed`, щоб запуски були відтворюваними).

## 2. Відповідність синтаксисів LINQ у Python
У Python немає двох синтаксисів LINQ, тому застосовано таку відповідність:
- **Синтаксис запитів** - декларативні вирази-генератори та comprehension (`[s for s in students if ...]`).
- **Синтаксис методів** - функціональний стиль із `filter`, `map`, `min`, `Counter` та `lambda`.

Час вимірюється через `time.perf_counter()` (аналог `Stopwatch`) двома способами: перший запуск і середнє за 1000 запусків.

## 3. Реалізація запитів (`queries.py`)

| Запит | Синтаксис запитів | Синтаксис методів |
|---|---|---|
| 1. Студенти до 20 років на «Programming Basics» | `[s for s in students if s.age < 20 and s.course_id in course_ids]` | `filter(lambda s: ..., students)` |
| 2. Join студентів із курсами | `[(s.name, by_id[s.course_id].title) for s in students ...]` (hash join) | `map(lambda s: (...), filter(...))` |
| 3. Кількість студентів на курсі | `Counter(s.course_id for s in students)` + comprehension | `Counter(map(lambda s: s.course_id, students))` + `map` |
| 4. Наймолодший студент | `min_age = min(s.age ...)`; `next(s for s ... if s.age == min_age)` | `min(students, key=lambda s: s.age)` |

## 5. Висновки про продуктивність
Абсолютні значення залежать від комп'ютера й змінюються між запусками, тому важливі співвідношення. Нижче наведено числа з виводу вище.

1. **Перший запуск ненадійний.** На малих даних один замір займає мікросекунди й залежить від «прогріву» (наприклад, у запиті 3 перший замір «запитів» вийшов повільнішим, ніж «методів», хоча в середньому за 1000 запусків навпаки). Тому для порівняння використано середнє за 1000 запусків.
2. **Стиль запису впливає менше, ніж алгоритм.** Comprehension виявились швидшими за `filter`/`map` з `lambda` в усіх запитах, де є відмінність (запит 1: 7.43 мс проти 18.38 мс на 200 000 студентів; запит 2: 43.66 проти 67.10 мс), бо lambda додає виклик функції на кожен елемент. Для запитів 3 і 4 різниця менша.
3. **Найдорожча операція серед основних - join (запит 2).** Він створює нові кортежі для кожного студента та робить пошук курсу в словнику (43-67 мс на 200 000 студентів проти 7-20 мс у фільтрації).
4. **Алгоритм вирішує все.** На 20 000 студентах і 200 курсах:
   - join вкладеними циклами (O(n·m)) виявився повільнішим за hash join у **27.3 раза** (119.58 мс проти 4.39 мс);
   - підрахунок окремим проходом для кожного курсу повільніший за `Counter` у **80.4 раза** (121.67 мс проти 1.51 мс);
   - `sorted(...)[0]` повільніший за `min()` у **2.7 раза** (3.31 мс проти 1.22 мс), бо сортування (O(n log n)) виконується заради одного елемента.
5. **Відкладене й негайне виконання.** Вирази-генератори відкладені: без `list(...)` запит нічого не рахує, тому в замірах результат матеріалізується (`list`/`min`/`next`). В .NET це відповідає `ToList()`, `Count()` тощо.

## 6. Відповіді на контрольні запитання
1. **Синтаксис запитів і методів.** Це дві форми запису тих самих операцій LINQ. Синтаксис запитів (`from ... where ... select`) схожий на SQL і читається краще для `join` і `group by`; компілятор перетворює його на виклики методів. Синтаксис методів (`.Where().Select()`) доступний для всіх операторів, зокрема `Sum`, `Take`, `Skip`, і зручний у ланцюжках. На практиці їх комбінують.
2. **Join і GroupJoin.** `Join` з'єднує дві колекції за ключем і повертає плоский набір пар (внутрішнє з'єднання: елементи без пари відкидаються). `GroupJoin` повертає для кожного елемента першої колекції групу відповідних елементів другої (аналог LEFT JOIN: елемент лишається, навіть коли група порожня).
3. **Агрегуючі операції.** `Count` (кількість), `Sum` (сума), `Average` (середнє), `Min`/`Max` (екстремуми), `Aggregate` (довільне згортання з накопичувачем). Вони зводять послідовність до одного значення.
4. **Вимірювання продуктивності.** `Stopwatch` (у Python - `time.perf_counter`) з багаторазовими запусками й усередненням; для серйозного аналізу - BenchmarkDotNet. Впливають: обсяг даних, алгоритм (hash join чи вкладені цикли), відкладене чи негайне виконання, кількість проходів по колекції, виділення пам'яті, стиль запису (виклики lambda).
